\begin{abstract}
\noindent This document summarizes the main concepts behind using AI --- and
in particular \emph{Claude Code}, an agentic command-line coding assistant ---
in empirical research. It draws on Scott Cunningham's ongoing ``Claude Code''
series on \emph{Scott's Mixtape} Substack, which documents in real time how an
applied economist integrates AI agents into causal-inference work. The emphasis
throughout is on \textbf{reproducibility}, \textbf{cross-implementation
auditing}, and the practical reshaping of the research workflow, alongside the
new risks these tools introduce.
\end{abstract}

\section{What is Claude Code and why researchers care}
% ===============================================================

Claude Code is a terminal-based ``agentic'' assistant: rather than answering a
single prompt, it reads a project directory, plans multi-step work, edits files,
runs code, inspects the output, and iterates toward a goal. For a researcher
this changes the unit of interaction from ``write me a function'' to
``\emph{take this project and do X}.'' Cunningham's recurring framing is that
the interesting question is not Claude Code in the abstract or from a software
engineer's point of view, but its usefulness for \textbf{applied empirical work}
--- econometrics, replication, and causal inference.

Key properties that matter for research:

\begin{itemize}
  \item \textbf{Repository awareness.} The agent operates over a whole
        project (data, scripts, notes), not an isolated snippet, so it can
        resurrect and extend old codebases --- e.g., taking a ten-year-old
        project and reconstructing its workflow.
  \item \textbf{Multi-language fluency.} It moves across Stata, R, and Python
        in a single session, which is central to the auditing use cases below.
  \item \textbf{Autonomy with a human in the loop.} It proposes and executes
        steps while the researcher supervises, corrects, and documents ---
        Cunningham calls the resulting practice ``my workflow'' rather than
        pure automation.
\end{itemize}

\section{Core concepts of AI-assisted research}
% ===============================================================

\subsection{Multi-agent code auditing (replication as verification)}
The signature idea in the recent series is using \emph{multiple independent
agents} to replicate the same analytical pipeline from scratch across different
languages and packages, then checking whether the deterministic outputs agree.
The worked example is difference-in-differences estimated over:

\begin{itemize}
  \item \textbf{Three languages:} Python, R, and Stata.
  \item \textbf{Five packages:} two Stata packages (\texttt{csdid},
        \texttt{csdid2}), one R package (\texttt{did}), and two Python
        packages (\texttt{diff-diff}, \texttt{differences}), centered on the
        Callaway and Sant'Anna estimator.
\end{itemize}

Because non-random quantities (number of observations, means, $R^2$, point
estimates) should be identical across correct implementations, disagreement
flags a bug in one of them. AI turns an otherwise prohibitively expensive
cross-package replication into a routine \textbf{robustness and validation
check}.

\subsection{Resurrecting and extending old projects}
Agents lower the cost of returning to dormant work: pointing Claude Code at a
legacy directory to rebuild the pipeline and then extend it with newer methods
(for instance, moving an old binary-treatment paper toward
\emph{continuous} difference-in-differences).

\subsection{Reproducibility and documentation}
The workflow externalizes tacit knowledge: the agent's plan, commands, and
diffs become an auditable record. Documenting ``what works and what doesn't''
in public is itself part of Cunningham's method --- the newsletter is a live
lab notebook.

\subsection{New problems created by AI, even when it saves time}
A recurring, honest theme: AI solves old problems while \emph{creating new
ones}, sometimes without even reducing total time spent. Examples include
over-trust in plausible-but-wrong output, loss of the friction that used to
force careful thinking, and the effort of verifying agent work. The multi-agent
auditing pattern is partly a response to exactly this risk.

\section{The research workflow, step by step}
% ===============================================================

A representative Claude-Code-in-research loop:

\begin{enumerate}
  \item \textbf{Point the agent at a directory} --- an existing project or a
        fresh replication target.
  \item \textbf{Ask for a plan}, then supervise as the agent reads data and
        code and proposes steps.
  \item \textbf{Fan out across implementations} --- have separate agents build
        the same estimand in Stata, R, and Python.
  \item \textbf{Diff the deterministic outputs} to confirm agreement;
        investigate any mismatch as a candidate bug.
  \item \textbf{Extend the analysis} with newer estimators or specifications.
  \item \textbf{Document} the session so the result is reproducible and the
        reasoning is inspectable.
\end{enumerate}

\section{Benefits and risks at a glance}
% ===============================================================

\newcommand{\pro}{\textcolor{ForestGreen}{$+$}}
\newcommand{\con}{\textcolor{BrickRed}{$-$}}

\begin{itemize}
  \item[\pro] Cross-language, cross-package replication becomes cheap enough to
        do routinely.
  \item[\pro] Old projects can be revived and modernized quickly.
  \item[\pro] Workflows are more legible and reproducible when the agent's
        actions are recorded.
  \item[\con] Confident-but-wrong output demands active verification.
  \item[\con] Time savings are not guaranteed --- new verification and
        supervision costs appear.
  \item[\con] Skills can erode if researchers offload reasoning wholesale
        rather than supervising.
\end{itemize}

\section{Takeaways}
% ===============================================================

\begin{enumerate}
  \item Agentic AI shifts research assistance from snippets to whole-project
        execution.
  \item The most valuable pattern for empiricists is \emph{redundant,
        cross-implementation replication} used as verification.
  \item Reproducibility improves when the agent's plan and actions are recorded.
  \item Verification and supervision are non-negotiable --- AI creates new
        failure modes even as it removes old ones.
\end{enumerate}

\section{Introduction}
Large language models (LLMs) have moved from answering questions in a chat window to
\emph{acting} inside a researcher's environment. An \textbf{AI agent} reads files, writes and runs
code, inspects the output, and iterates toward a goal with limited human intervention. \cc{} is a
representative example: a command-line agent that operates directly on a project directory, edits
source, executes analyses, and reports back. For empirical researchers this reframes the
computer from a passive tool into an active, if fallible, collaborator.

This shift is the throughline of Scott Cunningham's \cc{} series (running since mid-December 2025),
which documents---installment by installment---what changes when an agent, rather than a graduate
student or the researcher alone, executes the pipeline of an applied causal-inference project.

\section{Core concepts}

\subsection{From chatbots to agents}
\begin{itemize}
  \item \textbf{Chat model:} generates text in response to a prompt; the human copies code out and runs it.
  \item \textbf{Agent:} given a goal and tools (a shell, a file system, a compiler), it \emph{takes
        actions}, observes results, and self-corrects across many steps.
  \item \textbf{Practical consequence:} the unit of work becomes a \emph{task} (``replicate this
        pipeline'', ``estimate the effect and stress-test it''), not a single snippet.
\end{itemize}

\subsection{The agentic research loop}
A typical agent-driven empirical workflow cycles through:
\begin{enumerate}[leftmargin=1.6em]
  \item \textbf{Framing} --- translate a vague research interest into a concrete estimand and design.
  \item \textbf{Data} --- locate, download, clean, and validate the data; flag anomalies.
  \item \textbf{Estimation} --- implement the estimator(s) and produce point estimates.
  \item \textbf{Robustness} --- re-run under alternative specifications and estimators.
  \item \textbf{Audit} --- replicate the same specification across languages/packages to check agreement.
  \item \textbf{Write-up} --- draft tables, figures, and prose into a manuscript.
\end{enumerate}
The human's role migrates ``up the stack'': from writing code toward \emph{specifying}, \emph{judging},
and \emph{auditing}.

\subsection{Reproducibility and cross-implementation auditing}
A central methodological theme is using agents to run the \emph{same} design many ways:
\begin{itemize}
  \item Replicate a difference-in-differences pipeline across \textbf{Python, R, and Stata} and across
        multiple packages implementing the same estimator.
  \item Empirically, six implementations of the Callaway \& Sant'Anna estimator---same data, same
        specification, same covariates---\emph{almost never agree exactly}, exposing silent ``method
        drift'' hidden inside package defaults (e.g.\ how covariates enter, aggregation choices).
  \item Lesson: an agent makes it \emph{cheap} to run this audit, turning a rarely-done sanity check
        into routine practice.
\end{itemize}

\subsection{Judgment as the scarce input}
When code is cheap, \textbf{judgment} becomes the binding constraint. Agents can produce a plausible
result quickly; deciding whether the design answers the question, whether an anomaly is a bug or a
finding, and whether an estimate is trustworthy remains human work. Cunningham's audits repeatedly
surface \emph{real} defects the agent introduced and then fixed---e.g.\ a Sun--Abraham aggregation
bug and hundreds of false zeros in a raw dataset---illustrating that verification, not generation,
is where value concentrates.

\section{Opportunities and risks}

\subsection{Opportunities}
\begin{itemize}
  \item \textbf{Throughput} --- more designs explored, more robustness checks run, faster iteration.
  \item \textbf{Democratization} --- rigorous methods reach settings that could never previously
        justify the effort.
  \item \textbf{Better hygiene} --- cheap cross-implementation audits catch silent errors.
\end{itemize}

\subsection{Risks}
\begin{itemize}
  \item \textbf{Plausible-but-wrong output} --- fluent results can mask design or coding errors.
  \item \textbf{Reproducibility illusions} --- package defaults diverge; ``it ran'' is not ``it agrees.''
  \item \textbf{Publication-bias at scale} --- near-zero manuscript cost can flood venues and amplify
        p-hacking unless norms adapt.
  \item \textbf{Epistemic drift} --- treating an unaudited machine ``finding'' as an established ``fact.''
\end{itemize}

\section{Practical guidance}
\begin{enumerate}[leftmargin=1.6em]
  \item Specify the estimand and identification strategy \emph{before} letting the agent run.
  \item Treat every agent result as a draft to be audited, not an answer to be trusted.
  \item Cross-check estimators and, where feasible, re-implement across languages/packages.
  \item Keep a human in the loop for design judgment and for interpreting anomalies.
  \item Version-control prompts, code, and data pulls so a run is reproducible.
  \item Report the audit, not just the estimate: which packages agreed, and why any diverged.
\end{enumerate}

\section{Conclusion}
AI agents such as \cc{} compress the mechanical cost of empirical research and push the researcher's
value toward specification, judgment, and verification. Scott Cunningham's newsletter is a running
field report on exactly this transition: it shows both the leverage (whole pipelines executed and
stress-tested overnight) and the hazards (silent method drift, plausible bugs, and a widening gap
between producing a finding and establishing a fact). The central discipline the tools demand is
old and unglamorous---\emph{audit before you believe}---but agents finally make it cheap enough to
do every time.
